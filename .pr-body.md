## What
Replace the ad-hoc absolute `LOAD_THRESHOLD=3.4` gate with one config-as-code gate, and centralize the dispatch board list.

## Why
1. absolute loadavg meant different things on different core counts;
2. loadavg counts uninterruptible IO wait;
3. it was a second gate disagreeing with the fleet's own policy (`fleet.json`).

Real failure mode was memory, not CPU: workers were oomd-killed. Memory/swap now veto; CPU throttles.

## Also
- Board list from `config/dispatch_policy.json` (`dispatch_gate.py --boards`), so `contextvm-services` is dispatched without editing shell.
- Missing gate now **alerts and fails closed** (guarded spawn > silent wedge).
- `install-dispatch-policy.sh` installs script+gate+config atomically with rollback (shipping the script alone used to wedge dispatch).

## Honest correction
An earlier revision of this branch claimed per-node hold semantics were fixed. They are **not**:
`fleet_arbiter.py` emits per-node intents and **no component consumes them** (verified 2026-10-09),
so per-node hold semantics are not enforced anywhere; `fleet_boards.json.hold` is a local per-node
emergency switch, not a fleet-wide brake. The earlier test asserting a literal dict is deleted and
replaced with a real test of the local offload-hold path. Docs now state the actual scope.
